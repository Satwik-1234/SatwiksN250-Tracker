Objective
- Finish the requested N250 Tracker UI overhaul and verified component bug fixes while preserving the completed security, schema, and mileage work.
- Keep all displayed measurements honest: unavailable data must render as “No data”/“—”, never as zero or invented values.
Important Details
- Repo root: E:\250; all changes remain uncommitted.
- Deployment target is Vercel full-stack, not GitHub Pages static export. Required environment: DATABASE_URL, OWNER_PIN, OWNER_PASSWORD; optional: SESSION_SECRET.
- Full-tank economy must accumulate all fuel between full tanks, including partial top-ups. Never pair distanceCalculated with only the closing fill’s litres or use a totalDistance / totalLitres fallback.
- Per-brand and per-trip km/L were deliberately removed because a full-tank segment can span multiple brands/trip types. Exact litres, spend, ₹/L, and shares remain.
- UI audit is being handled in this order: verified data/correctness bugs, broken features/accessibility, design-system primitives, then main-view visual migration.
- Local date/time parsing is required; plain new Date('YYYY-MM-DD') and UTC toISOString() defaults caused date shifts.
- npm run lint had a pre-existing baseline of 51 errors and 89 warnings; CI lint is non-blocking, so compare the delta rather than expecting zero immediately.
- Open backend work remains: anonymous checkBackendHealth() conflicts with protected GET /api/init-db; backend mutations do not attach Supabase Bearer tokens; RLS-blocked direct writes must surface failure; MIGRATION_SCHEMA still needs NOT NULL review.
